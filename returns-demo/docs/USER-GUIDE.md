# 用户操作手册

服装网店退换货处理系统（Demo）· 面向消费者、售后客服、仓库人员三类岗位

- 访问地址：`http://localhost:3000`（启动方式见文末「附：系统启动与数据重置」）
- 演示账号（密码均为 `123456`）：

| 账号 | 岗位 | 说明 |
| --- | --- | --- |
| xiaolin / xiaomei | 消费者 | 各自只能看到本人的订单与售后单 |
| kefu | 售后客服 | 审核全部售后申请，给出结论 |
| cangguan | 仓库人员 | 登记收货、提交验货结果 |

---

## 1. 登录与界面总览

1. 打开系统进入登录页，输入账号、密码后点击 **登 录**；
2. 登录后顶部为黑色工具条（显示当前用户与岗位，可 **退出登录**）和白色导航（**工作台** / **核心链路** / **业务规则** 三个锚点）；
3. 中部为当前岗位的工作台标题，下方按岗位展示不同的操作卡片；
4. 三类岗位登录后看到的界面不同：消费者看到「我的订单 / 申请退货换货 / 我的售后单」，客服看到「售后单审核」，仓库看到「退回商品处理」。

> 忘记登录状态（如服务重启前的旧会话）时重新登录即可；退出登录请点击右上角 **退出登录**。

## 2. 消费者操作

### 2.1 查看我的订单

登录后第一张卡片「我的订单」列出本人已完成订单的全部商品：

- **可售后数量** = 该商品允许售后的总数 − 已被进行中售后申请占用的数量；
- 显示「已无可售后数量」的商品不能再申请；下拉框中也不会出现。

### 2.2 提交退货 / 换货申请

在「申请退货 / 换货」卡片中：

1. **订单商品**：下拉选择要售后的商品（括号内标注了剩余可申请件数）；
2. **售后类型**：选择 `退货` 或 `换货`；
3. **数量**：不能超过剩余可售后数量；
4. **申请原因**：从下拉选择（尺码不合适 / 商品质量问题 / 错发商品 / 运输破损 / 其他）；
5. **补充说明**（选填）与 **图片凭证张数**（模拟，0-9）；
6. 点击 **提交申请**，提示「售后申请已提交，等待客服审核」。

提交后状态为 **待客服审核**。常见被拒提示：

| 提示 | 原因与处理 |
| --- | --- |
| 申请数量超过可售后数量（剩余可申请 N 件） | 调小数量或选择其他商品 |
| 只能对本人已完成的订单申请售后 | 所选订单不属于当前登录账号 |
| 请填写申请原因 | 原因为必填项 |

### 2.3 补充材料

当客服要求补充材料后，售后单状态变为 **待补充材料**，卡片底部出现操作区：

1. 填写 **补充说明**，或输入 **新增图片张数**（至少填一项）；
2. 点击 **提交补充材料**，提示「补充材料已提交，重新进入审核」。

补充后状态回到 **待客服审核**，客服会再次处理。

### 2.4 查看进度

「我的售后单」卡片中每张售后单显示：

- 单号（AS 开头）· 订单号 · 申请人 · 申请时间；
- 商品、类型（退货/换货）、原因、单价、凭证张数；
- 当前状态徽章；退货完成后显示 **模拟退款 ￥金额**，换货完成后显示 **补发单号**；
- 点击 **展开时间线** 可查看每一次状态变化的时间、操作岗位与说明。

> 时间线就是这次售后的全部记录：谁、在什么时间、做了什么、留了什么话。

## 3. 售后客服操作

客服工作台「售后单审核」列出系统内全部售后单，可通过顶部 **状态筛选** 下拉只看某一状态的售后单。

### 3.1 审核新申请（状态：待客服审核）

在售后单底部操作区先填写 **审核意见（必填）**，再选择：

- **同意退回**：状态变为「客服已同意退回」，消费者按指引寄回商品，仓库随后处理；
- **要求补充材料**：状态变为「待补充材料」，等消费者补充后重新进入审核；
- **拒绝申请**：终态，售后单关闭，数量立即释放。

四种审核操作（含 3.3 的最终结论）都**必须填写意见**，否则提示「执行「××」必须填写原因或说明」。

### 3.2 处理验货结果（状态：已验货待结论）

仓库验货后，客服需要给出最终结论：

- 退货单：点击 **确认模拟退款**，系统记录退款金额（商品单价 × 数量，模拟，不接真实资金）；
- 换货单：点击 **确认换货补发**，系统生成模拟补发单号（SF 开头）；
- 也可以点击 **拒绝（验货异常）** 并说明原因，售后单以「已拒绝」结束。

### 3.3 状态与可执行操作对照

| 售后单状态 | 客服可执行 |
| --- | --- |
| 待客服审核 | 同意退回 / 要求补充材料 / 拒绝申请 |
| 待补充材料 | 等待消费者补充（无操作） |
| 已同意退回 / 仓库已收货 | 等待仓库操作（无操作） |
| 已验货待结论 | 确认模拟退款 / 确认换货补发 / 拒绝（验货异常） |
| 售后完成 / 已拒绝 | 终态，无操作 |

## 4. 仓库人员操作

仓库工作台「退回商品处理」同样支持 **状态筛选**。仓库只能操作已获客服同意退回的单据。

### 4.1 登记收货（状态：客服已同意退回）

1. 填写 **收货备注**（选填）；
2. 点击 **登记收货**，状态变为「仓库已收货」。

> 若客服尚未同意退回，此按钮不会出现；即使通过其他方式调用接口，系统也会拒绝并提示「客服尚未同意退回，不能提前登记收货」。

### 4.2 提交验货结果（状态：仓库已收货）

1. 填写 **验货说明**；
2. 选择 **验货结果**：`验货通过` 或 `验货异常`；
3. 点击 **提交验货结果**。

注意两点：

- **验货异常必须填写原因说明**，否则提交被拒绝；
- 验货不等于售后完成：验货通过/异常后，最终结论（退款、补发或拒绝）由客服给出。

## 5. 一次完整换货的示例流程

以「小林换一件尺码不合适的衬衫」为例：

| 步骤 | 岗位 | 操作 | 售后单状态变化 |
| --- | --- | --- | --- |
| 1 | 消费者 xiaolin | 申请换货 1 件，原因「尺码不合适」 | → 待客服审核 |
| 2 | 客服 kefu | 审核同意，填「在售后期内，同意退回」 | → 已同意退回 |
| 3 | 消费者 | （如被要求）补充材料后重新进入审核 | 待补充材料 → 待客服审核 |
| 4 | 仓库 cangguan | 登记收货 | → 仓库已收货 |
| 5 | 仓库 cangguan | 验货通过 | → 已验货待结论 |
| 6 | 客服 kefu | 确认换货补发，生成补发单号 | → 售后完成（终态） |

退货流程相同，只是第 6 步客服「确认模拟退款」并记录退款金额；若第 5 步验货异常且不符合条件，客服可拒绝并留下结论。

## 6. 常见提示说明

| 提示 | 含义 |
| --- | --- |
| 请先登录 / 登录已失效，请重新登录 | 会话不存在或已过期（如服务重启），重新登录即可 |
| 无权查看他人售后单 / 无权限执行此操作 | 消费者只能操作本人单据；接口与岗位不匹配 |
| 申请数量超过可售后数量（剩余可申请 N 件） | 超量或重复申请被系统拒绝 |
| 客服尚未同意退回，不能提前登记收货 | 仓库操作的前置状态不满足 |
| 需先完成仓库验货，才能给出最终结论 | 客服最终结论必须等仓库验货完成 |
| 验货异常必须填写原因说明 | 异常原因为强制记录 |
| 当前状态「××」不允许执行「××」 | 违反状态流转顺序，按第 5 节流程操作 |

## 7. 常见问题（FAQ）

**Q：图片凭证是真实上传吗？**
A：不是。演示版只记录凭证张数（模拟文件名），不做真实文件上传。

**Q：退款是真的吗？**
A：不是。所有退款金额与补发单号均为模拟记录，用于走通业务流程，不接真实资金与物流。

**Q：为什么我看不到别人的订单或售后单？**
A：系统按账号隔离数据，普通消费者只能查看本人订单与售后资料；客服与仓库可查看全部售后单但各有操作权限。

**Q：被拒绝的申请还能再申请吗？**
A：可以。已拒绝（及已完成）的售后单会释放占用的可售后数量，可对同一商品重新申请。

**Q：演示数据弄乱了怎么办？**
A：在项目目录执行 `npm run reset` 重置为初始演示数据（详见下节）。

## 附：系统启动与数据重置

当前主后端为 Java（Spring Boot）版：

```bash
cd backend-java
mvn -DskipTests package                            # 构建（首次构建自动下载依赖）
java -jar target/returns-backend-1.0.0.jar         # 启动，浏览器访问 http://localhost:3000

# 删除 backend-java/data/ 目录下文件后重启，即可恢复初始演示数据
```

通用冒烟测试（两种后端均可测）：

```bash
SMOKE_BASE_URL=http://127.0.0.1:3000 node test/smoke.js   # 测当前运行的 Java 后端
npm run smoke                                              # 测 Node 参照实现（独立测试实例）
```

默认使用本地 H2 文件数据库（`backend-java/data/`）；如需接入其他设备上的 MySQL
等数据库，参见 `docs/DESIGN.md`「数据库切换」一节。
